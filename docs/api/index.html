BytaRuntime.Initialize()

一行拿到本机能给出的最高 GL 版本：内置实现 → BYTA_GL_DRIVER → 系统实现，从 4.6 逐级往下试。

var session = BytaRuntime.Initialize();

GlBuffer

值句柄缓冲。Span 直传，不产生托管分配；Allocate / Upload / Orphan 覆盖静态与流式两种用法。

using var vbo = GlBuffer.Create();
vbo.Allocate(vertices);

GlProgram

着色器编译与链接。失败直接抛异常，消息里带完整驱动日志，不用自己去 glGetShaderInfoLog。

using var program = GlProgram.FromSource(vs, fs);

GlState

线程局部状态缓存。绑定、视口、开关都走它，冗余切换在到达驱动之前就被吃掉。

GlState.BindBuffer(BufferTarget.ArrayBuffer, id);

GlApi

后端门面：有 IGlBackend 时转发给它，否则直连原生函数指针 —— 同一份代码跑原生与 WebGL2。

GlApi.UseBackend(new WebGlBackend());

classBytaRuntime

Byta 的初始化入口：挑实现 → 从最高版本往下试 → 载入口点 → 查能力。 关键点：不会因为系统自带的实现只支持 4.1 就把自己限制在 4.1。 只要随库分发的实现（或 BYTA_GL_DRIVER 指定的实现）能给出更高版本，就用更高的。

classGlState

线程局部的 GL 状态缓存，用来消掉绘制循环里最贵的那批冗余状态切换。 状态是按"上下文 + 当前线程"存在的，所以缓存也按线程存放：整个缓存是一个线程私有对象， 每次访问只做一次线程静态读取 + 普通字段比较（不用每个字段各读一次 TLS）。 如果你绕过本库直接调用 GL 改了绑定，请调用 Invalidate。

classGlProcResolvers

各平台"当前进程"里找 GL 入口点的默认做法。 注意：GL 的入口点其实是跟上下文走的。托管运行时无法参与上下文的创建， 所以这里用的是各平台最可靠的进程级查询方式： macOS：OpenGL.framework 导出了全部核心函数符号，直接 dlsym。 Windows：opengl32.dll 只有 GL 1.1 的符号，其余必须问 wglGetProcAddress（依赖当前上下文）。 Linux：glXGetProcAddressARB 或 EGL 的 eglGetProcAddress。 如果你用的是 GLFW / SDL / Avalonia 之类的宿主，用它们自带的 getProcAddress 更稳， 直接把那个函数的地址包成 GlProcResolver 即可。

GlProcResolvers.cs

public static GlProcResolver ForCurrentProcess()

按当前操作系统选择解析器。

public static GlProcResolver MacOS()

macOS：OpenGL.framework 用 dlsym 直接找符号（GL 4.1 的函数全都导出）。

public static GlProcResolver Windows()

Windows：先试 wglGetProcAddress，失败再回落到 opengl32.dll 的导出表 （GL 1.1 那批函数不在 wglGetProcAddress 里）。

public static GlProcResolver Linux()

Linux：glXGetProcAddressARB 是事实标准（EGL 也能用同样的签名）。
